# 自定义流程测试执行记录

依据：用户确认的第一版自定义顺序流程需求；版本 0.24.0 本地构建，Windows / Node 22.22.3，2026-09-15。测试属于插件独立验证，未使用 Harness 仓库的 OpenSpec、Sonar 或录制会话快照体系。

## 验证范围与执行方式

- `npm run typecheck`：host/client 类型检查通过。
- `npm run build`：host、浏览器客户端及独立提交钩子构建通过。
- `DSH_TEST_DETAILS=1 npm test`：125 条 P0 检查（混合行为与静态断言）通过，49 个 node:test 行为用例通过，其中自定义流程 31 个、资源与既有行为 18 个。
- `npm run verify:package`：21 项检查通过，包括干净安装、host 入口、客户端注册、包内 P0/资源/自定义流程行为与 CLI 语法。
- 浏览器：真实 Harness Web profile 安装本地 tarball，使用工作台 Remote，未通过测试桩替代前后端通信。

注册工具测试使用内存文件服务与审批/shell 服务桩；Git 钩子在临时 Git 仓库内运行真实 Node 子进程。客户端编解码测试加载实际 lib/client.js，通过 ModuleLoader 挂载并检查输入/输出字段。

## 修复与复测记录

| 问题 | 分类 | 处理与结果 |
|---|---|---|
| 初次页面保存报 Required | 产品缺陷 | Remote schema 漏传 custom_flow；输入输出共用版本化解析定义，增加实际客户端编解码回归并实机保存通过 |
| 表单输入高度过大 | 产品缺陷 | 移除垂直布局中不合适的 flex-basis，桌面与窄屏复查通过 |
| 内置浏览器原生确认框阻塞自动化 | 兼容问题 | 改用页面内确认对话框，增加 Escape、焦点恢复与 Tab 约束；实机继续编辑/放弃/删除通过 |
| 钩子测试直接运行仓库内 CJS 文件被 ESM 解释 | 测试夹具问题 | 按真实安装结构复制到 .git/hooks 并配置 CommonJS，复测通过 |
| 客户端协议测试缺少 react-dom | 测试夹具问题 | 不做页面渲染的协议测试为 host 外部模块提供桩，保留实际编解码执行；实机另外验证渲染 |
| 台账测试缺少 fs.listDir | 测试夹具问题 | 补齐目录服务桩后，快照 ID 与版本投影用例通过 |
| 类型检查中 t 名称与 transition 变量冲突 | 实现检查问题 | 使用明确的 flowText 调用名，host/client 类型检查通过 |
| pnpm 检查旧锁文件的最近发布记录而拒绝本地包安装 | 环境问题 | 备份 profile 配置，用 npm 安装自有本地 tarball；无需更改其他包的发布等待策略 |
| 自动化未收到 download 事件 | 工具观测限制 | 检查到下载目录实际文件，读取 JSON 与保存定义逐项比较一致 |

## 数据与未测范围

临时单元测试目录在测试结束后删除。实机使用已登记的空工作区 D:/dshsseion，测试前没有 eng.json；测试生成的配置已核对内容、留存到独立测试夹具目录，并恢复工作区内 eng.json 不存在的原状。Downloads 中保留可导入的示例 JSON。本地 Harness 安装的是 0.24.0 tarball，npm registry 仍为已发布的 0.23.0。

本次不执行付费真实模型生成代码、自动创建 Git 提交、外部发布、多用户服务器隔离或负载测试。审批/shell 服务桩不等于真实用户审批或命令质量评估。新客户端编解码和工具状态输出采用插件自己的确定性行为断言；未运行 Harness monorepo 的录制会话测试。Node 24 与跨平台结果由后续 CI 验证，不能将本机 Node 22 结果表述为所有平台通过。
