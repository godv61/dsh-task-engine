# Harness 0.2.2-rc.1 适配记录

首次评测：2026-11-06；复核：2026-11-11（Asia/Shanghai）。0.41.0 的适配基于任务引擎 0.40.1，提交 `775a7489744e218f81cd741561f0dfac7b0174f3`。本文记录发布前验证；实际发布状态以 npm registry 和 GitHub Release 为准。桌面宿主升级到 0.2.2-rc.1 后，仍需更新任务引擎插件。

## 实施范围

- 新增 `tool-executor-compat.ts`，按公共 API 区分旧宿主 `presentAs` 与新宿主 `setExecutor`。新宿主通过官方 `NativeToolExecutor` 在工程/只读预设范围安装执行器；不读取私有 Scope 字段。缺少支持的执行器 API 或官方模块时直接失败。
- 新宿主执行器在整个工程预设期间保持原生，包括需求确认后的实施阶段。避免临时 Agent 执行器卸载留下不可用选择；切回普通预设时恢复父级执行器。宿主及其它预设可以继续使用 PTC。旧宿主保留临时 `presentAs` 展示及恢复。
- 保留原有 restrict、执行 guard 和需求文档/材料重查。预设切换清理 Agent 限制与旧审核证明；Agent 释放清理引用，已完成子代理的最终证明仍供父任务核对。预设卸载清理仍活动的守卫和证明。
- 改用公开的 `dsh-tool-subagent-control` 组合提供 `list_agents`，删除不再导出的 `/list-agents` 子入口。`send_message`、`interrupt_agent` 和原生委派别名均由原有受控委派策略拦截。
- 修复审核策略证明的首轮组装时序：在提示词组装完成后直接记录实际工具清单，避免新安装的监听器未进入当前 middleware 快照而漏记证明。没有有效证明时父任务仍拒绝接受审核。
- 5 项 DSH peer 显式保留 rc.3/rc.4/rc.5 并追加 0.2.2-rc.1，开发依赖与锁文件升级到新宿主。Node 24 构建新宿主，Node 22 保留旧宿主回归。
- `verify:dsh` 增加预设公开入口、restrict/guard、执行器公共 API 和残留直接 presentAs 调用检查；SDK 夹具按实际宿主选择单调用/批量调用 API，并核对批次结果身份。缓存依赖复制到新目录，防止真实路径解析串用其它插件副本。每次 SDK 验证仍创建全新项目、home、session 和本地 tarball。

上述宿主适配没有调整任务业务流程、复杂度阶段、委派收益策略、Skill/Rule schema、历史台账、初始化功能或浏览器业务代码；没有迁移项目数据或修改 QMS。分支随后叠加的 Sonar 范围与委派入口缺陷修复单独记录在 [缺陷修复验收](delegation-sonar-fixes.md)，其台账审核展示改动不属于宿主兼容性要求。
