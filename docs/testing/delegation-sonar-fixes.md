# 委派与 Sonar 范围缺陷修复验收

日期：2026-11-11（Asia/Shanghai）。代码位于 `codex/harness-0.2.2-rc.1` 隔离工作区，基于已发布的 0.40.1；尚未发布。以下修复叠加在该分支已有的宿主适配上，不修改 QDM/QMS 文件或历史台账。

## 修复与可复现结果

| 问题 | 修复 | 验证依据 |
| --- | --- | --- |
| 提交或 amend 后，既有改动排除失效；以移动后的 HEAD 比较又可能漏掉本任务代码 | 始终使用创建任务时解析的固定提交；仅排除范围外且内容哈希未变的既有改动 | 临时真实 Git 仓库执行 commit、amend，任务文件仍入选；新增或被再次修改的范围外文件仍阻断 |
| 扫描零文件却显示 `OK` | 有有效固定基线且确无候选变更才记 `NO_CHANGES`；缺基线拒绝；无可执行分析器记覆盖不足 | 实际调用本地审核选择入口和提交门禁，核对报告文字、扫描路径与参考提交；此零变更路径不连接 Sonar 服务 |
| `spawn_teammate` 绕过跟踪，后续消息却被拦 | 将创建、消息等原生委派统一交给执行守卫阻断，提示受控委派路径 | 使用真实 DSH 工具注册和 Agent scope，晚注册 Agent 自有工具仍不能执行，副作用计数为零；只读列表正常 |
| Team Lead 没有直接工具却能开始无法收尾的任务 | 创建前核对直接/受控执行路径及必需的 Git 终端，直接实施计划再次核对 | 无工具/无终端时拒绝且不落任务文件；补齐能力后创建成功 |
| 实施任务调用 `delegate` 返回 unknown operation | 返回明确的适用意图和实施派发操作 | 实施任务调用被拒绝且不生成运行记录；分析委派既有用例保持通过 |
