# 0.40.0 — Task workbench, requirement materials and rc.5 support

发布版本：0.40.0。日期：2026-11-03（Asia/Shanghai）。

## 交付与使用变化

- 需求分析阶段可通过 `write_requirement_material` 生成 Markdown、HTML 等确认材料，或按已挂载 Skill 的模板替换 JSON 数据。保留需求批准门禁；生成或填完清单不等于确认整个需求。产品确认清单保留为可选挂载 Skill，未写入内置业务流程。
- 新任务集中存储在 `.dsh/tasks/<任务标识>/`：台账、需求文档、确认材料和 Sonar 报告归属于同一任务。旧目录记录不自动扫描或迁移；升级后按新目录创建任务。
- 台账提供任务列表、需求与方案、实施计划、文件范围、验证与审核，以及连续文档阅读和 Markdown 导出。JSON 仍是唯一可变任务状态，展示区不自动改写台账。
- 明确支持 DSH 0.2.1-rc.3、rc.4、rc.5，以 rc.5 构建。未知后续预览版仍需单独验证。

## 流程与证据修复

- 直接实施并完成真实验证后，可直接申请独立审核，无需额外先调用实施 dispatch；原依赖、风险和独立审核门禁继续生效。
- 相同输入、计划、执行边界与结果的连续成功重跑保留已有验收；失败、文件变化或计划变化仍会使证据失效。
- 测试与提交工具返回当前阶段的下一步以及精确提交回填参数，减少重复测试和提交参数猜测。
- 支持 Python 标准库 unittest 的完整结果汇总；全跳过、空套件和失败不能作为测试通过证据。
- 已登记的精确测试命令引导至 `dev_task verify`，避免先在原生终端重复执行；单次验证可设置 `timeout_ms`（1,000–600,000 毫秒）。
- 环境受阻保留测试程序，通过宿主申请确切命令的一次执行批准；不自动扩大整场会话权限。独立审核使用结构化成功回执，完整日志继续保留。

## 验证与限制

完整回归 432 项：425 通过、0 失败、7 项原有宿主测试跳过，另有 143 项 P0 检查。类型检查、构建、安装包冷安装、真实 Git hook、rc.5 源码契约与实际 SDK 探针通过。

真实模型验收包括多轮产品确认的高复杂度案例，以及独立 JavaScript 低复杂度、Python 中复杂度案例。低等级 4 项、中等级全量 24 项通过并完成本地提交、归档；测试过程中有环境批准、操作者恢复和模型输出中断，不能称为无人干预完成。最后补充的命令路由与超时设置经过回归和实际 SDK 验证，未重新跑完整模型流程。

Windows 沙箱访问限制和模型流的 `MALFORMED_RESPONSE` 根因不包含在本次修复中。SonarQube 和 CodeGraph 未配置于本轮示例，不据此判断其效果。默认委派与审核选择条件未因此改成强制子代理。
