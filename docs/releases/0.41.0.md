# 0.41.0 — DSH 0.2.2 兼容与审核范围修复

发布日期：2026-11-11（Asia/Shanghai）。

本版支持 DSH 0.2.2-rc.1，继续支持 0.2.1-rc.3、rc.4、rc.5。新宿主要求 Node.js >=24.9.0，旧宿主保留 Node 22 SDK 运行验证。

- 按宿主公开 API 安装工具执行器，替换已移除的 `presentAs` 调用和 `/list-agents` 子入口。需求确认前、分析和独立审核的工具限制继续生效；预设切换与卸载清理单独验证。
- 修复独立审核首轮提示词组装时未生成有效工具策略回执的问题。
- 本地 Sonar 审核固定使用任务创建时解析的 Git 提交，提交或 amend 后仍保留任务代码范围和既有改动排除。任务开始后新增或再次修改的范围外代码仍需登记。
- 零文件审核不再显示普通 `OK`：有有效固定基线且确无候选变更时记录“无待扫描变更”；非空候选没有任何可用分析器时按覆盖不足阻断。
- 原生 Team 创建、消息和其它委派入口统一要求台账跟踪。无直接工具或受控执行路径的 Lead 提前收到可恢复提示；需要 Git 提交的流程检查主会话终端。实施任务误用 `delegate` 时明确指向 `plan_execution` / `dispatch`。

没有改变元技能阶段、Skill/Rule 挂载格式或初始化方式，不迁移业务项目及历史台账。DSH Agent Teams 的成员上限和回收接口由宿主提供，本版不修改。归档任务继续只读，收尾操作应在归档前完成，新增工作创建关联任务。

本地完整回归 451 项（444 通过、7 跳过、0 失败），另含 P0 143 项检查；构建、双端类型检查、安装包黑盒、新旧宿主公共 SDK 均通过。适配候选曾在精确标签源码页面完成低、中档真实模型交付和只读委派验收，后续缺陷修复另以确定性回归验证。验证范围见 [宿主适配记录](../testing/dsh-rc22-compatibility.md) 和 [缺陷修复验收](../testing/delegation-sonar-fixes.md)。

升级 DSH 桌面程序后，也需在插件管理中更新 `@godv61/dsh-task-engine`。运行旧宿主 0.2.0-rc.2 的用户继续固定插件 0.34.1。
