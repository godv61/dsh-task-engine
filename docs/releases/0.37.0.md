# 0.37.0：分析交付与可追踪子代理

原因排查、调用链解释和方案评估现在走只读分析流程，可以直接交付原因与方案，无需为了流程创建实施项、测试或 Sonar 扫描。只有用户要求修改代码时才进入实施流程。

新工程会话先通过 `status/create` 确定交付目标。新任务使用 `intent=analysis|implementation` 和 `intent_reason`；普通问答可以直接回答。旧任务按原快照和策略继续，不静默转换。

## 子代理

- 默认主会话执行；只在明确的并行、上下文隔离或独立核对收益下委派。复杂度和文件独立性本身不会强制启动子代理或再增加一轮审核代理。
- `delegate` 接收只读问题、路径和依赖，默认两个并发，可选 1–4；真实运行由 DSH managed activation 管理。业务代码写入保持串行。
- 工程预设关闭原生委派快捷工具，并通过执行 guard 拒绝已知绕过入口。调查代理仅可读取和搜索，不能写入、执行命令或再次委派。
- 运行结束与主会话接受分别记录。保留报告、真实运行 ID、开始/结束时间及失败信息；AUTH 错误停止未开始工作，清理不明时拒绝接受，恢复须核对宿主存活状态。
- 正确接收宿主 `result.structured`，不把普通说明文字当作 JSON 结果；缺失结构化结果时拒绝接受。

## 交付与台账

- `submit_analysis` 一次提交结论、方案、未确认项和源码位置。宿主读取限定行段并保存原文及 SHA-256；可选引文须精确匹配。指纹证明来源一致，不替代对结论正确性的核对。
- `plan` 原子登记实施计划，`accept_item` 在真实验证后原子记录逐项审核及完成。原有项目规则、风险、测试证据与适用 Sonar 门禁继续生效。
- 防止同名任务创建覆盖已有台账；Git 分支可由宿主读取。
- 台账展示分析/实施类型、真实运行、证据使用与可观测成本；未知数值不填零，并发耗时不相加。时间使用 UTC+08:00。

## 兼容与验证

继续支持 DSH `0.2.1-rc.3`。使用 `0.2.0-rc.2` 的宿主请固定插件 `0.34.1`。

本地回归 337 项：330 通过、7 跳过、0 失败；类型、构建、独立安装包和宿主契约检查通过。真实 API 验收覆盖主会话分析、单代理、双代理并行及较大源码快照的分析交付。少量烟测不构成普遍提速或策略最优的证明。
