## 验证范围与使用限制

报告第 6 条“采集真实成本与质量数据”尚未完成，本次四项功能缺陷修复不包含该项闭环。2026-10-24 已有少量真实会话的耗时、工具调用、父子 token 统计及人工介入说明（`deep-subagent-metrics.json`、`DEEP-SUBAGENT-ASSESSMENT-20261024.md`、`grouped-live-evidence.json`），但没有小修改/跨模块功能/缺陷返工三类任务的同题、同环境、多轮策略对照；失败恢复及人工修正次数也没有统一自动采集与核验。自动化回归和包黑盒通过不能证明默认委派策略更快、更省或质量更高。该项继续列为未完成评测工作。

本次在 Windows、Node 22.22.3 上执行；未声称完成新的 Linux/Node 24 CI。实际 Git、文件、Node 测试进程和提交钩子是真实的；子代理返回与 read 事件、Sonar HTTP 是可控适配器，用于验证门禁与传输边界，不证明大模型语义审核质量或真实 Sonar 服务验收。本次未重新开展完整业务系统页面需求测试。

删除/重命名基线限可校验的完整 UTF-8 文本，每份最多 256 KiB；未跟踪旧文件、目录、二进制或截断输出会明确拒绝。快照位于 `.dsh/review-inputs/`，需保留到任务验收。旧执行计划不会自动猜测删除意图；尚未完成的旧项应重新打开并显式登记 changes，不能移除旧路径绕过审核。门禁不提供对恶意编辑任务 JSON 的防篡改保证。

初始化默认最多扫描 1024 个目录、16 层、20000 个条目，并排除隐藏目录、可识别的符号链接、缓存和生成物。complete 仅表示该明确限定范围的目录发现完成，不表示业务分析已完整。扫描不足时可跳过项目地图，其他有证据支持的可选 Skill 仍可生成。
