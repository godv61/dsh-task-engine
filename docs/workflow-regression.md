# 真实项目回归迭代

版本：0.23.1，汇总本轮候选修复；完整业务流程的实机证据来自 rc.3，后续修复有针对性回归及包验证。

以 EAM 设备结构树和单选弹窗需求重跑工作台，业务代码由工作台执行；插件修复与独立观察分开记录。

| 上一轮问题 | 本轮处理 |
| :--- | :--- |
| 项目技能被同名个人技能覆盖 | 资源目录保留各来源；绑定选择按名称去重。 |
| 无任务 ID 的入口 status 报错 | 返回候选列表，支持分支过滤，不猜测当前任务。 |
| 更新实施项状态清空审核记录 | 同 ID、同标题保留审核；重开或改标题使审核失效。 |
| verify 丢会话沙箱上下文 | 透传会话策略与取消信号，记录沙箱结果。 |
| 审核后已错过提交窗口 | 标准 v2 改为审核通过后提交，离开前核对 Git 回执。 |
| 完成才披露测试技能，未执行 | 终态绑定提前执行；加载记录和附加技能命令回执参与门禁。 |
| 内置技能被误当成附加技能重复登记 | 状态列出必需回执技能；可选内置回执过期不额外拦截。 |
| 子代理已开工而实施项仍待办 | 派工前登记并自动设进行中，禁止另一项同时进行；实际执行仍核对日志。 |
| 追加修复项重写标题使审核丢失 | 已有项支持省略标题；已审核项改名须先重新打开。 |
| 方案猜测字段、驳回后直接重试 | 要求核对资料和真实组件行为，先收集反馈再修订送审。 |

新任务验证使用真实命令，并关联声明文件内容。改动代码后重跑验证；不会把“我测过了”直接转换为通过。附加技能可用交付文件内容校验命令，但不能用恒成功命令充当验收。

旧任务使用冻结配置及原执行约定，不自动修改历史记录。规则解析优先级为内置、项目、个人；技能正文的选择由 Harness 技能目录负责。

边界：文件摘要只涵盖声明的任务文件，不涵盖数据库、远端接口、依赖和未声明文件；成功退出码不证明测试充分。审核意见仍需人工判断。当前没有对任务记录做签名，也不防止有权限的人直接手改状态。

验收要求：同一个真实需求走完确认、设计、开发、技能测试、验证、审核、受控提交；不得另建收尾任务绕过门禁，不得以简单命令替代失败的核心验证。插件发布与业务验收分开记录，未完成的真实联调不宣称通过。

执行指引：范围清楚的小修正可由主代理完成，保留状态、审核及定向验证，不强制重复派子代理；权限或沙箱拒绝须走正式审批或报告阻塞，禁止反复换命令或修改 ACL 规避。上述行为指引不能替代 Harness 的权限执行，也尚未证明可消除模型误用。

本轮 EAMDEV-R2 已在同一任务达到完成（revision 60），8 项审核齐全，software-testing 在终态前执行并记录真实回执，业务提交 95892e8 回写成功；未推送或发布。结构树真实请求返回非 JSON，配置大小写差异待授权修正，不能声称端到端验收通过。

实机发现状态查询仍将过期回执任务显示为可提交，但真实 commit 门禁拒绝。rc.5 让 status 使用与 commit 相同的技能和摘要阻塞检查，新增 evidence_blockers，保持状态查询只读。报告证据归属错误仍需审查，技能加载和退出码不能证明报告内容准确。

后续任务出现未定义记录字段：校验正确拒绝，但模型缺少主动字段提示。0.23.1 新增 artifact_requirements，按冻结流程返回当前阶段字段及缺项，错误附恢复说明；兼容敏捷流程只有 scope 的情况，两个新增用例先失败后通过。

完整重跑方法：每轮归档业务差异、任务和问题证据，修复插件后将本轮业务改动恢复到同一基线，用独立会话重新交付完整需求。保留插件改进，不把上一轮实现复制为下一轮成果。暂停期间不调用模型；额度/鉴权问题属于服务状态，不由本包修改凭证处理。
