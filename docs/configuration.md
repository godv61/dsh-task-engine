# 流程配置

[← 文档导航](README.md)

在工作台“流程配置”中选择内置预设，或复制为自己的顺序流程。保存到当前工作区的 `.dsh/eng.json`，新建任务使用该配置。

## 内置预设

| flow | 阶段 | 用途 |
| :--- | :--- | :--- |
| `standard` | 需求评审 → 设计 → 开发 → 交付 → 代码审核 → 完成 | 完整的确认、产物、验证、审核及文件范围检查。 |
| `agile` | 需求 → 开发 → 交付 → 审查 | 减少阶段和产物。 |
| `minimal` | 开发 → 交付 | 保留实施项完成与提交检查。 |

预设本身不可改写。默认技能和规则保留，项目可以追加绑定；需要移除默认资源或调整阶段时，点击“复制当前预设并自定义”。没有配置文件时使用 standard；文件存在但无效会报错。

## 创建自己的流程

1. 选择工作区，复制预设或点击“从空白创建”。填写流程名称。
2. 左侧添加和选择阶段，右侧重命名、上移、下移或删除。第一个阶段是起点；完成阶段固定在最后，可重命名，不能移动或删除。将其他阶段上移到第一位即可更换起点。
3. 为需要验收的阶段勾选退出条件，填写产物与必填字段。添加“必填产物”时会一并启用产物检查。
4. 为每个阶段勾选技能和规则。自定义流程允许移除默认绑定；缺少资源时先在技能/规则页安装，再回来配置。
5. 设置允许提交的阶段、提交方式、消息格式与文件范围，检查下方预览后保存。

例如：问题复现 → 修复 → 自动测试 → 人工验收 → 完成。可将“验证通过”放在自动测试阶段，将“人工确认”放在人工验收阶段。进入阶段只提供约束与资源指引，不会自动执行脚本。

第一版支持 2–30 个阶段的顺序流程，不支持分支、循环或并行。完成阶段没有退出条件，必填产物和验收条件应放在它前面。删除阶段会同时删除其产物、绑定和提交检查点，保存前会重新校验。

## 阶段条件

| 条件 | 满足方式 |
| :--- | :--- |
| 人工确认、需求确认、方案确认 | advance 请求 Harness 人工审批，批准后才流转。 |
| 实施项完成 | 所有任务实施项为 done，并通过规格与代码质量两阶段审查。 |
| 验证通过 | 当前阶段使用 verify 记录结果；配置了命令时由 Harness shell 执行。 |
| 审核通过 | 当前阶段使用 review 记录 pass。 |
| 必填产物齐全 | 当前阶段使用 record 填完每份产物的所有必填字段。 |

自定义流程的人工确认、验证和审核按阶段关联，前一阶段的通过结果不能满足后一阶段。实施项列表属于整个任务，多个“实施项完成”条件检查同一份列表。常规风险下无验证命令时仍允许声明验证结果；审核结论和实施项完成也不代表独立质量认证。

高风险任务要求实际流程包含验证、审核与文件范围检查。其验证通过必须附带成功的真实命令回执，不能只声明 passed。standard 或满足这些条件的自定义流程可以承载高风险任务。

## 提交设置

| 方式 | 行为 |
| :--- | :--- |
| 按任务 | 在选中的检查点允许 TASK 提交，当前阶段的退出条件必须已满足。 |
| 按实施项 | 除检查点外，存在完成实施项时也允许 Tn 提交。 |
| 手动 | 自定义流程的 dev_task commit 需要人工批准；Git 钩子仍检查阶段、消息、文件范围及风险。未选择检查点时允许在任一阶段申请，但仍要满足该阶段退出条件。 |

提交消息正则留空表示不限制格式。使用捕获组时，第一个捕获组表示任务 ID，例如 `^TASK-([A-Z0-9-]+): .+`；不要把其他内容放进第一个捕获组。没有任务 ID 时，钩子按当前分支查找任务，建议一条分支只保留一个活动任务。允许提交不会自动执行 Git 命令，advance 也不要求必须已经生成提交。

升级插件后，对使用过旧钩子的项目执行 `dev_task operation=install_hook` 更新，再用 `operation=verify_hook` 检查。钩子是安装到每个项目的副本，不会随 npm 更新自动替换。

## 保存、导入与导出

每个项目保存一份当前生效的流程。自定义流程的“导出 JSON”导出流程定义；“导入 JSON”通过系统文件选择器读入草稿，检查资源后再保存。文件最多 256 KB，不包含任务历史和技能/规则正文。可维护多个导出文件，在不同项目复用；工作台尚无多模板库。

未保存修改时，切换标签、工作区、流程模板、关闭工作台或刷新页面会提示。保存保留 `verify_command` 及其他已有项目字段；配置被其他操作修改时拒绝覆盖，重新读取后再编辑。无效 JSON 需要先修复文件，不会被标准预设覆盖。

自定义定义使用 schema 1、`custom:` 前缀标识和递增版本。完整示例见 [custom-workflow.json](examples/custom-workflow.json)。在 eng.json 中以 `flow` 指向定义的 id，并将该定义放入 `custom_flow`。内置预设使用 `flow` 和可选的 `stage_bindings`；自定义流程的绑定放在 `custom_flow.config.stage_bindings`。

## 进行中的任务

新任务保存完整流程快照、版本及摘要。编辑或导入新流程影响之后创建的任务；已有任务按原快照继续，版本显示可在 dev_task status 中查看。第一版不迁移活动任务，也不要手动修改它们的快照。
