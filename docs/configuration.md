# 流程配置

[← 文档导航](README.md)

当前版本通过内置流程和阶段资源绑定配置项目。推荐使用工作台“流程配置”页面；高级用户也可以编辑项目根目录的 `.dsh/eng.json`。

## 选择流程

| flow | 阶段 | 主要特点 |
| :--- | :--- | :--- |
| `standard` | 需求评审 → 设计 → 开发 → 交付 → 代码审核 → 完成 | 包含确认、产物、验证、审核与文件范围检查，支持高风险任务。 |
| `agile` | 需求 → 开发 → 交付 → 审查 | 减少阶段与产物要求，不支持高风险任务。 |
| `minimal` | 开发 → 交付 | 精简为实施项完成和提交检查点，不支持高风险任务。 |

项目没有配置文件时使用 `standard`；配置文件存在但 flow 缺失或无效时会报错，不会自动忽略错误。

## 追加技能与规则

最小配置如下：

```json
{
  "flow": "standard"
}
```

`stage_bindings` 的键是当前流程中的阶段名称，值是该阶段需要的技能与规则名称。字段可省略；默认绑定仍然生效。[默认配置示例](../defaults/eng.json)列出了标准流程的绑定。

当前绑定采用追加方式：项目增加的名称会与预设默认项合并去重；取消默认项的勾选不会移除其绑定。内置同名资源优先，使用不同名称来安装自己的资源。

进入阶段后，`dev_task` 披露该阶段的技能名和规则内容。新任务离开阶段前会检查 Harness 的 skill 工具成功加载记录；附加技能还须记录 `skill_result`（技能名、执行场景、真实验收命令回执）。安装一个技能不会自动执行其中的脚本。

挂在终态（例如“完成”）的技能在进入终态前执行。测试技能通常建议挂在“交付”；现有“完成”绑定也会在审核阶段执行后才放行。标准流程 v2 在审核通过后提交，并核对真实 Git HEAD。修改文件或声明范围后，旧验证回执失效。

资源管理保留项目和个人目录的同名条目，避免来源误标和误操作。绑定仍按名称选择，内置优先；自建同名资源按项目优先于个人解析。技能最终由 Harness 的技能目录加载。

## 哪些内容暂时不能修改

阶段顺序、转移条件、产物必填字段和提交策略由所选预设固定。新建规则可以提供工作指引，但不会改变引擎中的提交消息校验或阶段条件。

可视化自定义流程的范围见[功能规划](roadmap.md)，目前尚未发布。

## 配置与正在进行的任务

新任务记录创建时的完整流程快照，后续按该快照执行。修改项目配置影响之后创建的任务，不会自动迁移进行中的任务。

验证命令还可以由配置中的 `verify_command` 指定；未指定时根据项目类型选择默认命令。当前工作台保存流程时只写入 flow 和 stage_bindings，手写的额外字段可能被移除；使用此项时请检查保存后的文件。这一问题纳入后续配置编辑器改造。
