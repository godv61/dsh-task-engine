# 常见问题

[← 文档导航](README.md)

## 这是服务器产品吗？

本项目面向本机个人工作台。日常使用重点是选对工作区、明确操作目标、保护现有文件和保留任务记录；多用户服务器的会话权限隔离不属于当前产品的必修项。

## 为什么安装了插件，聊天里没有 dev_task？

安装会添加工作台，但任务工具只在挂载插件 agent 的会话预设中启用。新建会话时选择“工程化开发引擎”，再检查工具是否可用。工作台中的“标准研发”等选项是任务流程，不能代替会话预设开关。

## 能自己增删流程阶段吗？

0.23.0 支持选择三个内置流程和追加阶段资源，不支持自由修改阶段。复制预设、编辑阶段与条件、导入导出已列入[自定义流程方案](roadmap.md)，尚未实现。

## 安装资源后就会自动使用吗？

还需要到“流程配置”选择阶段并挂载资源。任务执行时按阶段披露对应内容；安装行为本身不会执行资源中的脚本。

## 改了流程，原来的任务会变化吗？

任务保存创建时的流程快照。修改项目配置不会自动改变进行中的任务；新任务使用保存后的配置。

## 能移除默认技能、覆盖内置规则吗？

当前预设绑定只能追加，内置资源只读且同名优先。需要自建资源时使用新名称。自定义流程方案会提供自由配置绑定的能力。

## 工具显示验证或审核通过，能完全相信吗？

0.23.1 新建任务的验证需要真实命令回执，要求退出码为 0 且未超时、中止或被沙箱拒绝；代码修改后需重验。旧任务保持原验证约定。附加技能记录加载、命令和场景证据；审核和实施项结论仍由模型记录。命令覆盖是否充分、审核是否准确仍需判断，不能把一个成功退出码当作全部需求已验证。

## 本地提交钩子有什么作用？

它在普通 git commit 时检查任务、阶段、消息和文件范围。`--no-verify`、替换 hooksPath 或直接修改本地数据仍可能绕过检查；项目需要更强的提交约束时，应结合自己的 CI 和人工审核。

## hash 和版本号能防止任意篡改吗？

hash 检查流程快照是否与保存的摘要一致，文件版本检查阻止并发覆盖。任务 JSON 没有签名，具有文件修改权限的人可以同时修改内容与摘要；它们不提供独立防篡改认证。

## 为什么 GitHub 上的 HTML 手册显示源码？

GitHub 文件页不会直接作为网页运行 HTML。下载 [manual.html](manual.html) 后用浏览器打开，或先阅读本站点内的 Markdown 指南。
