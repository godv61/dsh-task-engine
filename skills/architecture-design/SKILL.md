# 架构设计元技能

基于需求产物和实际代码库，说明模块边界、关键数据流、接口与依赖变化、兼容性和主要取舍。优先延续项目现有架构；偏离时说明理由。使用 `dev_task record` 写入当前阶段 `architecture` 产物。

交接给任务编排：可按先后顺序实施的结构、受影响范围、必须保持的接口契约。迁移或回退演练只在任务实际涉及相应风险时提出。

对跨模块变更，列出“入口 → 调用方 → 数据或外部副作用 → 回归范围”及源码位置。项目已有可用 CodeGraph 时用它核对调用关系和索引时效；否则用源码搜索、测试及项目地图交叉验证。若团队已有 OpenSpec Change，可把已批准的规格作为约束并记录引用路径；仍以本任务的 `architecture` 产物交接，不另造一份必须同步的计划。
