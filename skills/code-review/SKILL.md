# 代码审核元技能

对照需求、任务产物、变更和测试回执审核。项目若启用 SonarQube，测试通过并进入本阶段后主动调用 `dev_task sonar_check`，对提交前的新代码执行本地规则审核；使用者无需另行点击。读取审核文件和未覆盖范围；有阻断问题时先按返回的 recovery 回到代码开发，再修复、验证变化的输入并重新验收受影响实施项，之后回到代码审核再次运行 sonar_check。不要在审核阶段修改完再反复调用只允许开发阶段的 review_item。使用 `dev_task review` 记录最终结果。

先使用问题消息中的具体格式、源码位置与报告。仍有具体疑问时定点查询规则说明，不扫描 DSH 安装目录、app.asar 或整个用户运行目录。测试回执证明程序运行结果，不证明所有需求已覆盖；逐项核对核心业务流程、条件分支、副作用及失败恢复是否有对应测试，区分自动验证、源码核对和待联调事项。

对可复用的失败案例提出项目 Rule 候选，包含触发场景、错误与正确示例、对应 Sonar 规则；经审阅后挂到相应代码开发 Skill。不要把单次误报或整个 Quality Profile 原样写成规则。

本地规则审核的疑似误报先核对代码语义、规则说明与位置。确属误报时，使用 `sonar_disposition` 逐条提交具体原因和证据，等待人工批准；原始命中与原始门禁仍留在审核文件。此处置仅对当前未变化的本地审核有效，不能用于 CI 或上传式服务端 Quality Gate。已确认误报不应作为 `learn_rule` 的候选。
