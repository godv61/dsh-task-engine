# 代码开发元技能

先读取当前阶段实际绑定的 Skill 和 Rule；没有项目扩展时，依据本元技能、任务产物与源码直接开发。按任务先后顺序修改代码，遵守已有接口和技术栈约束。每个实施项完成时记录结果及对应审核；不要为了分发给多个开发者而拆项。发现需求或方案发生变化时使用 `revise` 回到相应阶段。

交接给测试：变更文件、实现要点、验收场景及已知限制。SonarQube 若启用，在代码审核阶段运行，不在每次编辑时触发。

有可用代码索引时可辅助查询受影响的符号和调用方，并用实际代码核对结果；索引过期或不可用时直接搜索源码。按已确认的需求和任务清单实现；外部规格若被本任务引用，也须核对其版本和来源。索引和外部规格均不能替代当前任务的产物、规则及真实测试。
