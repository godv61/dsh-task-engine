# 代码开发元技能

先读取当前阶段绑定的项目地图、领域编码技能和规则。按任务先后顺序修改代码，遵守已有接口和技术栈约束。每个实施项完成时记录结果及对应审核；不要为了分发给多个开发者而拆项。发现需求或方案发生变化时使用 `revise` 回到相应阶段。

交接给测试：变更文件、实现要点、验收场景及已知限制。SonarQube 若启用，在代码审核阶段运行，不在每次编辑时触发。

已有 CodeGraph 索引时可先查询受影响的符号和调用方，并用实际代码核对结果；索引过期或不可用时直接使用源码搜索。已有 OpenSpec Change 时按其已确认规格实现，并把对应实施项 ID 写入交接说明。两者均为可选证据来源，不能替代项目 Skill/Rule、任务台账和真实测试。
