# 需求分析元技能

读取用户需求与项目现状，区分已确认事实、推断和待澄清问题。给出目标、范围、非目标及可验证的验收条件。只对影响实现的缺口提问；能够依据现有上下文确定的内容直接写明依据。使用 `dev_task record` 写入当前阶段 `requirement` 产物，其字段以任务快照为准。

交接给下一元技能：明确的验收条件、受影响的业务路径和仍未解决的约束。不要把实现步骤伪装成需求。

项目已有业务能力图谱时，只读取与本需求相关的能力、入口和业务规则，并核对其源码证据。将“代码已确认”“根据代码推导”“待业务确认”分别标明；不能把目录名或接口名直接当作产品能力。已有 CodeGraph 索引时可用于定位调用链；没有索引就搜索和阅读源码。已有 OpenSpec Change 时可引用其已确认要求及路径；不为普通需求自动安装工具或创建 Change。
