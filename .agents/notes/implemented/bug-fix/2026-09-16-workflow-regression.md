# 工作台真实需求回归修复

## 背景
EAM 项目实机暴露状态更新丢审计、技能仅披露不执行、验证漏传会话策略和错过提交检查点。

## 决策
标准流程升级 v2；新任务 execution_version=1 才启用新门禁，保留旧快照兼容。执行事实来自成功 skill 工具事件、shell 回执和 Git HEAD；本地记录不是可信防篡改存储。资源管理保留全部来源，项目规则优先于个人同名规则。

附加回执只约束附加技能，内置技能保留原有产物和验证操作，避免重复回执在范围调整后误阻塞。状态提供 command_receipts_required 供模型判断。dispatch 在子代理调用前记录派工意图并激活实施项，重派撤销旧审核；真实子代理执行不由这条模型记录证明。方案审批驳回后先获取反馈，资料访问失败不能作为猜测接口字段的依据。

全量更新实施项时，已有 ID 可省略标题以保留原文；已审核项改名而仍标完成会立即拒绝。标题改变可能代表实施范围变化，不能直接沿用旧审核；拒绝发生在写入前，避免追加修复项时因模型重述标题丢失整批审核记录。

小修正允许主代理实施，审核和验证仍必需。实机中测试文件移位被沙箱拒绝后，子代理重复尝试等价命令并留下重复类；正式权限升级获批后原命令成功。因此指引要求权限失败走宿主审批或返回阻塞，不修改 ACL 或换命令规避；这不构成对子代理执行的代码硬拦截。

## 验证

rc.5 修复实机状态提示矛盾：status 的 commit.allowed 纳入与真实提交相同的技能和回执新鲜度检查，evidence_blockers 同时列出所有过期证据；不改写台账、不过滤流程图 legal_next 候选。新增定向测试先失败后通过，覆盖缺失技能、部分刷新和全部恢复。EAMDEV-R2 使用 rc.3 完成本地提交闭环，真实结构树联调仍未通过。
.workflow-test.mjs 覆盖审计保留、入口发现、沙箱与取消信号、技能失败门禁、真实提交、过期回执和同名来源。构建、类型检查、原有测试及安装包黑盒结果按真实运行记录，真实项目闭环仍须单独确认。
